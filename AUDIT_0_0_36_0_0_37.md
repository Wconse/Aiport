# Audit: AIPort 0.0.36–0.0.37

Date: 2026-08-14
Scope: source delta from 0.0.35 through 0.0.37, deterministic suites, clean rebuild, deployed hashes, and available client/server logs. This audit did not change source code, protocol, binaries, deployment, configuration, or saves.

## Verified

- Clean rebuild succeeds and reproduces `AIPort.dll` exactly: 97,792 bytes, SHA-256 `78bd9bb6c58602168a8391a758a4c18e9c6393f5de38d9317e57356d383fa148`.
- Bootstrap reproduces exactly: 10,240 bytes, SHA-256 `8357d5c56766dabba2777d472b87b1919a1925242b6d1f8a00bf99fd653934cf`.
- Client, server, and build artifacts match.
- Suites passed: explicit routing 15/15, prompt quality 17/17, regular targets/profiles/events 21/21, Groq provider 18/18, explicit config path 10/10.
- Available runtime logs show successful 0.0.37 handshake, hero and regular-character requests, retry after rate limiting, result delivery, and display-only UI updates.
- No AIPort fatal/unhandled exception appears in the inspected runtime logs.

## Findings

### High — NPC target is not server-authoritative

`AIPortConversationServerHandler` accepts a non-empty `AIConversationRequest.NpcHeroId` after syntax validation and uses it directly. It does not prove that the requesting peer is currently talking to that hero/character. A modified client can therefore request narrative context for another valid or invented identifier.

Impact is limited while the port is narrative-only, but this is a mandatory blocker before actions, diplomacy, relation changes, item/gold transfer, quests, or persistent memory. The server must resolve or validate a peer-bound conversation target rather than trust field 5.

### Medium — ordinary-NPC identity is archetype-level, not instance-level

For non-hero characters, 0.0.37 uses `CharacterObject.StringId`. Generic agents commonly share this template identifier, for example `village_woman_battania`. Their stable profile is therefore shared by every agent using that template. It is deterministic, but it is not a unique persistent identity for an individual townsfolk/guard/bandit.

Current volatile conversation memory remains separated by `ConversationId`, so this does not by itself merge two open conversations. Documentation should describe this as a stable archetype profile until a server-owned instance identity exists.

### Medium — “recent” events are bounded by count, not age

The code scans up to 96 log entries and returns up to five matches, but applies no campaign-time cutoff. In a sparse history an old event can be described as recent. `PlayerBattleEndedLogEntry` is accepted for every NPC, and prisoner events can match an entire relevant faction, so prompts may include stale or weakly relevant facts.

Add an age window and tighter relevance scoring before relying on this as character memory.

### Medium — 0.0.36/0.0.37 suites are mostly source-invariant tests

The suites confirm that required strings and code constructs exist, but do not execute Bannerlord dialogue graphs, campaign-log filtering, target spoof resistance, or multiple NPC instances. Their pass counts are valid as build/source checks, not complete behavioral proof.

### Low — naming and documentation lag behind generalized targets

Protocol and logs still use names such as `NpcHeroId` and `SpeakerHeroId` for regular `CharacterObject` targets. This works in protocol 1 but is semantically inaccurate. Preserve protobuf field numbers; rename only symbols/log labels in a compatible change or document field 5 as a generic target ID.

### External Coop errors observed

Two client `NullReferenceException` entries originate in `CaravansCampaignBehaviorHandler.Handle_NetworkDeleteExpiredTradeRumorTakenCaravans`, not AIPort. The server also prints expected early assembly-probing errors before its resolver loads dependencies; it later reaches `CampaignReady / SERVING`. Track the caravan exception separately as a Coop issue.

## Recommended order

1. Two-client test remains the immediate runtime gate.
2. Add server-authoritative, peer-bound target validation.
3. Introduce a server-owned instance identity for ordinary NPCs, or explicitly keep them archetype-only.
4. Add campaign-age and relevance filters to recent events.
5. Add executable tests for target spoofing, duplicate regular-character templates, event age filtering, and return-token routing.

## Release assessment

- `0.0.36`: no blocking regression found in explicit-only routing or prompt construction.
- `0.0.37`: usable for the current narrative-only alpha, but not safe as a foundation for executable AI actions until target authority is fixed.
